# P0 — Universal evidence-led scene blueprint (router)

**Default work is visual scene design, not gameplay.** Execute P0-A.md then P0-B.md. First discover the actual scene, its source media, target outputs and design constraints; choose only data representations that serve those goals. Do not invent terrain, architecture, environmental systems, cameras, dimensions, style or an asset category. See docs/UNIVERSAL_WORKFLOW.md and docs/SCENE_PROFILE_TEMPLATE.md.

**P0-A:** analyze evidence and user brief, classify observed versus inferred data, identify features and relationships, propose representation and review views, and build an initial reference-to-geometry contract.

**P0-B:** materialize versioned scene-profile/blueprint assets, feature dependencies, optional representation-specific data and structural consistency checks. Its deliverable is a usable specification for Blender P1-concept; it does not require a heightmap, path graph, simulation map, specific projection or in-engine runtime.

Use P0-A_world-model-optional.md and P0-B_world-model-optional.md only when an actual 3D source is supplied and inspected. `prompts/legacy/` is for explicitly selected historical procedures, never a default input.

P0 acceptance: source provenance, documented assumptions, named design features, explicit geometry choices, compatible coordinate units/transform plan, and a review method. P0 design approval is not a claim that Blender geometry or runtime behavior already exists.
