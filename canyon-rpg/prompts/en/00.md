# 00 — Initialize a reusable scene-art project

Role: technical art pipeline coordinator. This is a universal production initialization task; do not infer a scene type, aesthetic, geometry family, reference medium, coordinate system, engine, target camera or interactivity from the repository name or examples.

1. Discover the actual user brief, attached/linked references, existing projects, available authoring applications, review outputs and constraints. Record what exists and what is missing.
2. Read `docs/UNIVERSAL_WORKFLOW.md`, `docs/SCENE_PROFILE_TEMPLATE.md`, and the relevant current phase prompt. Do **not** load `docs/SCENE_TYPE_EXAMPLES.md` as requirements; it is optional illustrative material.
3. Create or update a versioned `scene_profile.json` only with observed/approved values: goals, evidence, source provenance, intended output, review views, geometry priorities, style, platform and exclusions. Keep unknown fields `UNSPECIFIED`.
4. Confirm Blender for the default P1-concept authoring task; probe other tools only if a selected phase needs them. Do not silently install software or access paid services.
5. Record coordinate units, axes, transformations and export target **if supplied or decided**. Never assume the historical project's scale or engine coordinate convention applies to another scene.
6. Set stage routing: P0 analysis/blueprint -> P1-concept Blender art blockout -> P2 style/lookdev -> P3 asset kit -> P4 conditional systems/assembly -> P5 QA; P1-playable is opt-in and never blocks visual work.
7. Preserve original inputs and prior approvals, establish stable IDs/versioning, actual test logs, and honest PASS / FAIL / ASSUMED / NOT_RUN / NOT_APPLICABLE statuses.

Deliver project/profile inventory, available tool versions and next phase contract. No forced model creation or production before the inputs have been understood.
