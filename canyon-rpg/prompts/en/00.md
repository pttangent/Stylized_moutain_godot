# TASK 00 — Initialize a Portable Stylized Canyon RPG Project

You are a technical 3D environment developer specializing in Godot 4, Blender and reproducible game asset pipelines.

## Required reference
Read the Can It Code tutorial index at:
https://github.com/pttangent/Stylized_moutain_godot/blob/main/canyon-rpg/reference/canitcode/AGENT_INDEX.md

Access the URLs directly using available web/HTTP tools; never assume the repository has been cloned or the references are available locally. If a URL is inaccessible, record that limitation instead of claiming to have read it.

## Inputs
- The active workspace or existing game project, if present.
- The user-provided stylized canyon reference image (attachment, path, or URL).
- Existing specifications and source assets, if provided.

## Tasks
1. Inspect the current filesystem and project history without overwriting existing work.
2. Verify availability and versions of Blender, Godot 4, Python, Git and needed image-processing libraries. Record missing tools rather than silently installing replacements.
3. Reuse the existing structure, or create reference/, blueprint/, blender/scripts/, blender/source/, blender/renders/, assets/, godot/, tests/, reports/, prompts/ if starting fresh.
4. Establish Godot Y-up world coordinates: horizontal axes X/Z, height Y, 1 game unit = 1 meter.
5. Establish stable asset identifiers, real dimensions, pivot/origin, connector rules, collision, UV/material conventions, licensing and performance tracking.
6. Prefer versioned Blender Python scripts, background execution when available, editable .blend sources and individually reusable .glb exports. Blender MCP is optional.
7. Validate a minimal Godot startup project and provide actual commands and outcomes; do not claim a graphical test if no graphical renderer was launched.
8. Establish acceptance gates: P0 spatial blueprint, P1 playable blockout, P2 visual prototype, P3 modular kit, P4 procedural assembly, P5 quality and performance checks.
9. Do not spend paid 3D-generation credits or begin detailed modeling.

## Deliverables
A working project scaffold, technical conventions, reports/project_audit.md, actual tool versions, test commands, outstanding blockers and verified/unverified status. Stop after initialization.
