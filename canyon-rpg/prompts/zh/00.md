# TASK 00 — 初始化可跨專案使用的風格化峽谷 RPG 工程

你是熟悉 Godot 4、Blender 及可重複執行 3D 資產管線的遊戲環境工程師。

## 必讀來源
先閱讀 Can It Code 教學索引：
https://github.com/pttangent/Stylized_moutain_godot/blob/main/canyon-rpg/reference/canitcode/AGENT_INDEX.md

請直接使用可用的網頁或 HTTP 工具存取遠端連結。不得預設 GitHub 已 Clone 到本地，或逐字稿已存在本地；無法讀取時要說明。

## 輸入
- 目前開啟的工作區或既有遊戲專案。
- 使用者提供的峽谷參考圖片（附件、路徑或網址）。
- 如有，既有規格和資產。

## 任務
1. 盤點現有檔案與版本紀錄，不覆蓋已完成工作。
2. 檢查 Blender、Godot 4、Python、Git 與圖片處理函式庫的實際版本及可用性。
3. 優先沿用現有結構；若是空白工程，建立 reference、blueprint、blender/scripts、blender/source、blender/renders、assets、godot、tests、reports、prompts。
4. 統一 Godot Y-up 坐標：X/Z 水平、Y 高度，1 unit = 1 m。
5. 建立穩定資產 ID、真實尺寸、Pivot、模組接合、碰撞、UV/材質、授權與效能紀錄規範。
6. 優先保存 Blender Python 腳本、可編輯 Blend 檔和獨立 GLB；Blender MCP 非必要。
7. 驗證最基本的 Godot 工程，列出真正執行過的命令；若沒有啟動圖形渲染，不得宣稱已完成實際畫面測試。
8. 建立 P0 空間藍圖、P1 可遊玩白模、P2 美術樣板、P3 模組庫、P4 程序化組裝、P5 技術驗收等關卡。
9. 不動用付費 3D 模型額度，不開始精緻建模。

## 交付
工程骨架、技術規範、reports/project_audit.md、工具版本、測試命令、未解決障礙，以及各項結果的已驗證／未驗證狀態。完成初始化即停止。
