# P1-playable — 可選的 Godot 可行走改造

只有使用者**明確要求**，且已有通過驗收的 Blender P1-concept 白模，才可以執行。身份：Godot 關卡、碰撞與導航工程師。目標是在**不破壞已核准美術構圖**的前提下，補足路線與物理；不得重新生成取代美術白模。

## 輸入
approved blender/source/p1_concept.blend、生成器、固定三鏡頭圖、P1 美術修訂檔、原圖和 P0 路線候選。舊 Navigation Graph 只表示設計連通，不是實際道路曲線或已通行的地形。

## 實作
1. 先明確指定真正要走的起點、終點、主線與支線。風景區沒有行走需求就保持不可走，不得為了完整 NavMesh 破壞岩壁。
2. 以原圖可見步道與 Blender 實際幾何規劃中心曲線；遮擋處標成 DESIGNED／INFERRED／UNKNOWN。不把單條圖線當成已確認的實體道路。
3. 優先用**獨立支撐地面、隱藏碰撞坡道、獨立木橋、階梯和平台**來完成玩法；不得隨便削平原有峽谷、改變瀑布或池塘。若必須改美術形體，建立版本並進行畫面差異審核。
4. 預設測試角色身高1.75m、半徑0.35m，普通步道目標坡度約不大於18°、階高約不大於0.175m。這些條件**只適用可行走幾何**，不可套到所有自然地形。沿實際曲線測量局部坡度、寬度、頭頂淨高，不能只算端點平均值。
5. 以 Blender/GLB 分開輸出地形、岩壁、路面與橋，確保 Z-up 到 Godot Y-up 的轉換只執行一次。碰撞和可行走面應與水、樹冠、岩壁的渲染 Mesh 區分。
6. 在 Godot 建立 StaticBody3D／CollisionShape3D、CharacterBody3D 與需要時的 NavMesh；確實運行角色跨越橋、樓梯、平台及指定支線的測試。
7. 保留 P1-concept 相同的固定主鏡頭和左右兩視角，拍攝真實 Godot 16:9 截圖，與美術白模比較輪廓、水位、橋樑尺度、遮擋。為了通行必須大幅犧牲美術品質時，不可假裝成功，應標 BLOCKED。
8. 各路線回報真實 PASS／FAIL／BLOCKED／NOT RUN；記錄尺寸、階梯、碰撞、導航、進出端點及可再現的測試命令。

交付 Godot playable 場景、分離的物理層、測試腳本、固定鏡頭畫面、reports/P1_playable.md。**P1_PLAYABLE_APPROVED** 需有真實走訪證據和美術一致性；本階段永遠不是 P2 美術開發的必要前置。
