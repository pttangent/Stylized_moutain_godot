# P1-playable — 選用的互動場景改造

**只有使用者明確要求互動功能，且已有核准的 P1-concept，才可進行。** 本任務不預設特定遊戲引擎、人物、交通方式、輸入設備、碰撞類型或場景種類。

1. 依使用者實際目標辨識 Runtime、互動對象、功能、控制方式、性能需求及必要測試。未知的參數保持待定，不能挪用歷史專案的尺寸或坡度。
2. 保留既有 Blender 美術來源、核准構圖、特徵與相機；所有互動修改須另存版本，不能直接破壞原始美術。
3. 只為實際需要的系統加入碰撞、導航、物理、動畫、互動腳本或其他資料；未使用系統記錄 NOT_APPLICABLE。
4. 沿實際互動區域驗證必要的尺寸、連接、有效範圍與狀態，不以抽象關係圖的連通取代 Runtime 實測。
5. 匯出需驗證 Blender 與目標引擎的座標、尺度、材質及幾何一致性，避免套用重複變換。
6. 真正執行 Runtime 測試，記錄每個功能的 PASS／FAIL／BLOCKED／NOT_RUN，並與核准的 P1-concept 畫面比較。
7. 互動需求若與美術驗收矛盾，應提出具體取捨而不是靜默重設場景。

交付獨立的互動版本、實測腳本／日誌、渲染證據與 `reports/P1_playable.md`。未選用 playable 不影響 P2–P5 美術。

## 固定 45° 工程鏡頭的持續驗證

保留 P1 已鎖定的 `CAM_QA_45` 45° 工程鏡頭，不把它改成遊戲機位。互動版本完成後用相同 QA 45° 截圖檢查形體是否退化，並另外測試真正的 Runtime 鏡頭。
